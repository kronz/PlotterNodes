Overview

Make2D reproduces Rhino's Make2D command inside Dynamo. It projects 3D geometry onto an image plane and splits the resulting lines into those visible from the viewpoint and those hidden behind other geometry. ProtoGeometry (Dynamo's wrapper around the Autodesk Shape Manager kernel, ASM) exposes no silhouette or hidden-line function, so the visibility computation is done on a triangle mesh by a kernel-free engine in Internal/HiddenLine.cs. ASM is used only to mesh solids and surfaces and to sample curves.

Three Dynamo nodes create a drawing:

NodeProjectionDrawing frame
Make2D.ByDirectionParallel along a view direction (plan, elevation, isometric)Origin is the projected world origin; +y is the up vector (default world Z, world Y for plan views)

Stage 1: input collection

DynamoGeometry.cs walks the input list recursively (nested lists allowed):

Input typeHandling
Solid, Surface, PolySurface, other GeometryMesh.ByGeometry(g, meshTolerance, 512), then TrianglesAsNineNumbers: three corner points per triangle. Each input becomes one body.
MeshRead the same way, without re-meshing
Curve, PolyCurve, LineSampled to a 3D polyline. Lines keep their two end points; other curves use a segment length derived from the scene size or meshTolerance
Point, Plane, Vector, CoordinateSystem, BoundingBox, stringsIgnored

Triangles are read with VerticesAsThreeNumbers + VertexIndicesByTri when those reproduce TrianglesAsNineNumbers exactly, which keeps the per-face vertex sharing used in stage 2; otherwise the raw corners are used and stage 2 rebuilds the shared vertices. Make2D.Diagnostics reports the source, edge counts and classification mode per body.

Stage 2: mesh topology

  1. Weld. Vertices closer than tol = 1e-6 × scene diagonal are merged using a 3D hash grid (with neighbour-cell probing so points straddling a cell border still merge). Triangles that collapse to a line or point are dropped.
  2. Edge map. Every triangle edge is keyed by its sorted vertex pair; each key lists the faces that use it.
  3. Orientation. A breadth-first walk over edges shared by exactly two faces flips neighbours so both faces traverse the shared edge in opposite directions. This makes winding consistent within each connected patch; the global sign does not matter, because only changes between front-facing and back-facing are used.
  4. B-rep edges. For solids, surfaces and polysurfaces the real edges come from ASM (Topology.Edges, sampled as 3D polylines). Mesh edges lying along them are crease candidates (kept when they fold more than 1.5 × the surrounding facet angle, so seams and tangent edges stay hidden); all other mesh edges are smooth and the crease angle is not used. Dynamo meshes and other triangle data use the crease angle.
  5. Per-face topology. Faceters mesh each B-rep face separately: triangles of one face share vertex indices, neighbouring faces only share positions. Edges shared in the input are inside a face; edges joined only by the weld are B-rep edges. When a body has both kinds, this replaces the crease angle (stage 3). The largest fold between same-face neighbours, spread over two rings of triangles, is the local facet angle.
  6. Normals and facing. Each face gets a unit normal and a front-facing flag for the current view (parallel: n · forward < 0; perspective: n · (p − eye) < 0).

Crease, boundary and curve classification is independent of the view. Silhouettes depend on the view because they come from the front/back flags. T-junctions arise when two adjacent faces were tessellated with different divisions along their common edge; without matching, smooth surfaces would show spurious boundary lines. Partner edges are found with a 3D hash of boundary edges (cell size from the mean and maximum boundary edge length) and must lie on the same line within tol.

Stage 4: view, clipping and projection

  1. Eye space. Points are expressed as (x right, y up, z along the view axis). The basis comes from the view direction and the up vector; when the up vector is missing or parallel to the view, world Z is used (world Y for views along Z).
  2. Clipping (perspective only). Triangles (Sutherland-Hodgman) and segments are clipped to a near plane and four side planes of the square field of view. The side planes are inflated by 1e-9 so geometry lying exactly on the window edge is kept.
  3. Projection. Parallel: (x, y) with depth key z. Perspective: (x·d/z, y·d/z) with key −1/z, where d is the image plane distance. Both keys vary linearly across a projected triangle, so they can be interpolated with screen-space barycentric weights. Edges seen end-on project to a point and are dropped.

Stage 5: splitting

Visibility of a line can only change where, in the drawing, it crosses another feature line or passes through a face. Each projected segment is cut at:

  1. 2D crossings with other feature segments (found through a uniform screen grid). Parallel segments are tested for collinear overlap and cut at the other segment's end points; the parallel test is relative (|cross| ≤ 1e-12 · |r|·|q|).
  2. Piercing points where the segment's depth equals the depth of a triangle's plane inside that triangle (a curve entering a solid, or interpenetrating bodies). Both depths are linear in the segment parameter, so the root is found directly.

Stage 6: visibility test

sequenceDiagram participant P as Piece (split segment) participant G as Screen grid participant T as Projected triangles P->>G: midpoint (x, y), depth d G->>T: triangles whose bounding box covers the cell loop each candidate triangle T->>T: barycentric test at (x, y) T->>T: interpolate depth key, convert to depth alt triangle depth < d − depthEps T-->>P: hidden end end P-->>P: visible if no triangle is in front

Triangles sharing a vertex with a silhouette edge are skipped when testing that silhouette: a mesh contour zigzags around the true contour, so its neighbouring facets can appear to cover it. Edge-on triangles (screen area ≈ 0) are excluded from the occluder grid. depthEps = 1e-6 × scene diagonal lets lines lying on their own faces count as visible. The grid cell size is about twice the drawing diagonal divided by √(triangles + segments), capped at 2048 × 2048 cells.

Stage 7: cleanup and output

  1. Deduplicate. End points are quantised to the merge tolerance; identical visible pieces are kept once. Hidden pieces that coincide with a visible piece are dropped (for example the hidden bottom edges under the top edges in a plan view).
  2. Hidden under visible. Hidden pieces lying within 0.3 % of the drawing diagonal of visible lines along their whole length are dropped (the second rim of a cracked mesh, a hidden rim running along its silhouette).
  3. Overlaps. Pieces running along an already kept piece of the same visibility within 0.15 % are drawn once (the fan of tiny contour edges where a contour runs along the view direction).
  4. Chain. Pieces of the same kind are joined end to end; a chain stops at junctions where three or more pieces meet, so every polyline is an unambiguous pen stroke. Chains whose ends meet become closed loops.
  5. Simplify. Douglas-Peucker at half the merge tolerance removes collinear vertices.

Limitations and open issues

  1. Accuracy equals mesh resolution: curved silhouettes are polygonal at the meshTolerance chosen.
  2. Edges come from mesh angles, not from the B-rep. A B-rep edge whose faces meet at less than creaseAngle is drawn only where it happens to be a silhouette; tangent edges are never drawn.
  3. Intersection curves between interpenetrating solids are not created (same as Rhino); pass them in as curves.
  4. Visibility is decided at each piece's midpoint, so correctness relies on stage 5 splitting at every place visibility can change.
  5. Test suite: tests/make2d checks 364 cases (26 analytic shapes × 14 views) against exact ray-cast ground truth; the prototype passes 363. Run the C# engine with build.ps1 -Make2DTests.
  6. Open issue (2026-10-27): a cube with a spherical cavity, viewed from slightly different perspective cameras, loses parts of face rim edges in some views; the rims are classified hidden. The reader now uses TrianglesAsNineNumbers instead of VertexIndicesByTri to rule out an index mismatch. If the problem persists, the exported mesh (Mesh.ExportMeshes to OBJ) and the camera values will be replayed in the Python mirror (tools/hlr_prototype) to identify the occluding triangle.
  7. Possible improvement: take feature edges directly from ASM (Topology.Edges, Edge.CurveGeometry) and use the mesh only for silhouettes and occlusion.
